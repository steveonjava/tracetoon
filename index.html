Evidence graph

Every sentence has a receipt.

Before any model writes a word, Tracetoon builds a small graph of your branch. It links every change in the diff back to the conversation that produced it:

  • your request
  • →
  • agent edit
  • →
  • hunk in the diff
  • →
  • commit sentence
  • →
  • test run
  • Credit goes to the right code. The brief names the function that owns each behavior and marks what's new and what only changed. It also flags code where a word like "always" would be wrong.
  • Validation comes from receipts. Tracetoon writes the Validation section from the test and build runs on the final code. The model never gets to type "all tests pass."
  • The why, not just the what. Plans, decisions and the original request come along with the code. On Codex, graph drafts conveyed 82% of the expert fact sheet's claims, against 72% without it.

Embedded database

A graph database that fits in your pocket.

The graph runs on Relate, an open-source embedded graph database written in Rust. Tracetoon ships it compiled to WebAssembly inside the CLI, so there's nothing else to install.

  • No server, no setup. It runs inside the CLI on Linux, macOS and Windows, works offline, and builds a fresh graph for every PR.
  • Real queries, not guesswork. A few lines of Cypher answer questions like "which request led to this code?" and "did a test pass after the last edit?" Relate's BM25 fulltext index links each commit sentence to the code it describes.
  • Same evidence in, same brief out. Every fact traces back to a hunk and a session line, so you, or another agent, can audit any sentence.
0 tokensto build the graph and the evidence brief. It's a deterministic step, not a model call.
Cost savings

A sharp brief lets cheap workers check the work.

Without a map, an expensive model rereads your source to check its own claims, two or three times per PR. With the graph, that work is done once, before any model runs. Then:

  • One strong writer drafts from a 2–3K-token brief instead of the whole session history, and writes 7K tokens instead of 22K.
  • Two cheap reviewers (Haiku or Luna, at extra-high reasoning effort) check a short packet. That costs about 6¢ per PR on Claude and under 1¢ on Codex.
  • One edit pass. The reviewers' findings merge into a single list. There are no repeat review rounds and no forked subagents.
  • Claude, no graph $0.65
  • Claude + graph $0.34
  • Codex, no graph $0.45
  • Codex + graph $0.13

Fits your workflow

Just ask for a PR. It knows the house rules.

  • Nothing new to learn. Ask your agent for a PR, or let it run gh pr create as usual. Tracetoon writes the description, has it reviewed and creates the PR. Then it tells you what it did: the link, whether a comic is included, and any sessions it left out.
  • Your words stay yours. Anything you write in the PR, or edit on GitHub later, is kept on the next update.
  • Follows the house rules. Tracetoon reads each repo's AI policies, AGENTS.md, PR templates and contribution guides, and adds any disclosure the repo asks for. Where a repo's rules forbid images in PRs, the comic is left out automatically.
  • Private by default. Logs are read on your machine, and private paths and secrets are redacted from the evidence.
  • Easy to switch off. Run tracetoon off to turn it off everywhere or per repo, or set TRACETOON=0 for a single command.
Comics

And a comic nobody asked for. Everyone reads it.

Each PR can get a one-off comic: a joke about how the work really went, with characters, a format and an art style made up for that PR. It might be a gag strip, a before and after, a movie poster or an instruction manual. Your agent proofreads every word.

  • It's drawn with an image route you already have: the Codex CLI with a ChatGPT login, Antigravity, or an OpenAI or Gemini API key.
  • It respects the repo. Where contributing rules forbid images in PRs, Tracetoon skips the comic and tells you why.
  • It's your choice. Run tracetoon config set comic off and your PRs have no comic. Set it to always to ignore repo rules.

Under the hood

From session logs to a reviewed PR

  1. Find the sessionsTracetoon matches agent edits to lines in your diff, and asks you when a session is ambiguous.
  2. Build the graphtracetoon prepare turns the logs and git history into a redacted evidence brief, using 0 tokens.
  3. WriteOne strong model drafts 250–400 words and ties each fact to a row of the brief.
  4. CheckDeterministic checks run first, then two cheap reviewers. One edit pass applies their findings.
  5. PublishTracetoon creates the PR, adds the comic if the repo allows it, and tells you what it did.
Problems it solves

Questions people ask their agents

How do I write a pull request description from my AI coding agent's session?

Coding agents (Claude Code, Codex, Copilot, Cursor, Antigravity and others) already keep session logs on disk. Tracetoon finds the sessions that produced the current branch and writes the PR from them: what the user asked for, what changed and what actually ran. Ask the agent "Open a PR for this branch with Tracetoon", or run tracetoon prepare --json yourself.

AI-generated PR descriptions are vague, padded, or say tests passed when nobody ran them. How do I fix that?

Tracetoon writes only from evidence and checks every sentence before posting: a claim check marks sentences the logs contradict or do not establish, then independent reviewers (two in the shipped skill) compare the draft with the diff. It never says "all tests pass" unless a run showed it, and a run that passed before the last edits is described that way.

How can reviewers see what an AI agent was asked to do and what it actually did?

The PR covers the request, the plan the user approved, the decisions made along the way, and each test, build and lint run with its result. Anything the logs did not capture is reported as "not captured", not "not done".

Which lines in a diff came from the AI agent, and which prompt led to them?

Tracetoon builds an evidence graph (evidence-graph.json) that links each hunk in the diff to the agent edit and the request that produced it, and to the test runs after it. The match is evidence, not proof of authorship.

How do I keep secrets and private conversation out of a PR written from agent logs?

Logs are read on your machine. Secrets, personal data, your home path and your username are redacted from the evidence, and a leak scan runs before anything is published. Only the rendered PR text (and a comic, if you approve one) leaves the machine.

How do I make AI-written PRs follow my repository's PR template, AGENTS.md and AI disclosure policy?

Tracetoon reads each repository's AI policies, AGENTS.md, PR templates and contribution guides, adds any disclosure the repository asks for, and reports a policy against AI contributions.

Can my agent create or update a GitHub PR without overwriting what I edited by hand?

tracetoon publish pushes the branch and creates or updates the PR with the GitHub CLI (gh). Tracetoon owns only a marked region of the body; text you write or edit on GitHub is kept on the next update. It never merges.

My agent has no shell or skills support. Can it still write PRs from its logs?

Yes, over MCP: tracetoon mcp serves the same flow on stdio (tracetoon_status, tracetoon_prepare_pr, tracetoon_publish_pr). For example: claude mcp add tracetoon -- tracetoon mcp.

How do I get reviewers to actually read a pull request?

Lead with the problem and the result, keep it short, and skip file-by-file lists, which is how Tracetoon writes. It can also add a one-off comic about the change. Comic images go to an image service only after the user approves that route.

How we measured (and what's not perfect yet)

The numbers come from prbench: 61 real PRs from 12 repositories, each with its original agent session logs, and 3 drafts per PR for each setup (the brief was tuned on 25 of them; on the 36 untouched PRs judges picked the graph 51–21 on Codex and 42–11 on Claude Code). Each PR has a fact sheet drafted from the diff and the sessions and reviewed by a six-model expert panel. Two AI judges per provider scored every draft against that fact sheet with a 10-item reviewer rubric: Opus 5.5 and Sonnet 5.5 for Claude Code, Sol 6.1 and Terra 6.1 for Codex. A head-to-head pick counts only when both judges, each reading the pair in both orders, pick the same draft. Every factual error a judge flagged was checked against the evidence by two more models. Each comparison uses the same model with the graph and without it.
